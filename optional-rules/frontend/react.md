# React 可选规则

## 适用范围

- 仅在项目使用 React 时启用；先确认依赖版本、渲染模式及现有组件约定。
- 不预设 Next.js、路由、状态库或服务端组件；相关限制按项目实际能力补充。

## 约束

- 渲染组件时，保持渲染过程纯净；请求、订阅与外部写入放在明确的副作用或事件入口。
- 使用 Hooks 时，遵守所用 Hook 的调用规则；常规 Hooks 不在条件、循环或嵌套回调中调用。
- 状态跨组件共享时，明确唯一所有者与更新入口；可从现有输入计算的值优先直接派生。
- 更新 React 状态或 props 派生结构时，创建新引用，避免原地修改导致更新不可观察。
- 新状态依赖前值时，采用函数式更新，避免闭包中的旧值造成覆盖。
- 使用 Effect 时，仅用于与外部系统同步，并列全实际依赖；不要通过压制检查掩盖闭包问题。
- Effect 创建订阅、定时器或请求时，提供对应清理，并允许建立与清理重复执行。
- 请求依赖输入变化时，取消旧请求或校验请求标识；卸载后不继续提交过期结果。
- 事件处理与异步回调读取状态时，确认读取的是预期快照或最新值，而非偶然的旧闭包。
- 列表允许重排或编辑时，使用稳定 key，避免索引导致组件状态错配。
- 通过 ref 操作 DOM 或保存非渲染状态时，明确用途；影响界面的数据仍应进入状态流程。
- 渲染外部 HTML 或 URL 时，进行适当清理与协议校验。
- 存在服务端渲染时，隔离浏览器 API，避免共享请求状态并检查初始渲染一致性。
- 引入 memo 或缓存时，先确认性能收益及依赖正确性；不依赖缓存保证业务正确性。

## 验证

- 修改状态逻辑时，验证连续更新、共享状态入口及不可见的原地修改。
- 修改 Effect 时，验证清理、依赖变化及项目开发模式中的重复执行。
- 修改异步逻辑时，验证乱序响应、失败、取消和卸载。
- 修改列表或表单时，验证重排后的编辑状态、焦点及提交结果。
- 项目已有检查入口时，运行 Hooks 检查、构建及适用的类型检查。
- 运行组件或交互验证时，覆盖受影响行为，并记录无法验证的渲染模式。
