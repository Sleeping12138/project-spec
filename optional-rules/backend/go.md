# Go 可选规则

## 适用范围

- 仅在项目使用 Go 时启用；先确认 go.mod、工具链及现有包与接口边界。
- 不默认 Gin、Echo 或特定数据库库；采用项目已选运行模型及依赖约定。

## 约束

- 接收网络、文件或消息输入时，在边界验证值域、长度和权限。
- 可取消的请求链使用 context 传播截止时间与取消信号，避免下游重新创建无关背景上下文。
- 创建带取消或超时的 context 时，明确 cancel 的调用职责，及时释放关联资源。
- 长循环、阻塞发送及外部调用时，提供取消或退出路径，并确认所用客户端支持取消。
- 每次启动 goroutine 时，说明其退出条件、结果或错误接收者，以及关闭时如何等待。
- 使用 channel 时，明确发送方、接收方与关闭者；通常由掌握发送结束时机的一方关闭。
- goroutine 发送结果时，考虑调用方提前退出，避免无人接收而永久阻塞。
- 返回 error 时，添加必要操作上下文并保留可识别原因；使用错误链判断而非字符串匹配。
- 忽略错误时，说明其可接受原因；写入、提交及关键关闭错误不能无声丢弃。
- 获取响应体、文件或连接时，及时安排释放，并按资源语义处理关闭错误。
- map、slice 或指针跨 goroutine 共享时，采用所有权隔离或适当同步。
- 结构体包含锁等不可安全复制成员时，避免使用会复制它们的值传递或接收者。
- 外部调用与工作队列时，配置超时及并发上限，避免为每个输入无界启动任务。
- 定义接口时，围绕使用方需要保持精简；仅在可替换边界真实存在时引入抽象。

## 验证

- 修改 context 链路时，验证上游取消、截止时间及下游及时退出。
- 修改 goroutine 或 channel 时，验证消费者提前结束、错误分支及服务关闭。
- 修改错误处理时，验证原因可识别且对外信息不泄漏内部细节。
- 修改共享状态时，运行相关并发测试及项目支持的竞态检查。
- 使用项目已有格式、静态检查、构建和相关测试入口，核对目标工具链。
- 使用泄漏或关闭检查时，等待明确完成信号，避免仅依赖固定休眠判断成功。
