# Java 可选规则

## 适用范围

- 仅在项目使用 Java 时启用；先确认 JDK、构建工具、运行模型及依赖版本。
- 不默认 Spring、Quarkus 或特定持久化框架；框架规则仅在依赖与配置已确认后应用。

## 约束

- 接收网络、文件或消息输入时，在边界验证结构、范围及权限，避免依赖内部类型转换兜底。
- 定义公共接口时，明确空值、异常及返回语义，避免同一失败既返回空值又抛异常。
- 抛出或转换异常时，保留原因与业务上下文；对外响应不泄漏堆栈和敏感配置。
- 获取文件、流、连接等资源时，明确所有者并优先使用自动关闭机制。
- 资源关闭也可能失败时，保留主要失败原因，并按资源语义处理关闭异常。
- 多步持久化要求原子性时，明确事务起止、隔离级别及回滚条件。
- 采用框架事务时，验证实际调用路径、异常类型和异步边界是否受事务管理。
- 事务持锁期间需要外部调用时，评估拆分或补偿方案，避免长期占锁。
- 同一对象被多线程访问时，明确共享字段的同步、可见性及复合操作原子性。
- 使用可变集合或对象跨线程传递时，采用隔离、快照或适当同步，不能仅依赖 final 引用。
- 创建线程池或异步任务时，配置容量、拒绝策略、超时、取消与关闭职责。
- 收到中断或取消时，按调用契约传播或恢复中断状态，避免无说明地吞掉信号。
- 调用远程服务时，设置超时；仅对可安全重试的失败使用有限重试。
- 处理金额、时间与标识符时，选择与业务精度、时区和范围匹配的类型。

## 验证

- 修改异常路径时，验证原始原因保留、对外错误映射及资源释放。
- 修改事务时，验证中途失败回滚、并发冲突与实际事务边界。
- 修改共享状态或异步任务时，验证竞争、取消、队列饱和及应用关闭。
- 修改远程调用时，验证超时与重试不会造成重复业务写入。
- 使用项目现有构建、静态检查和相关测试入口，记录目标 JDK 与验证结果。
- 框架能力无法确认时，记录待确认项，不以注解存在推断运行行为。
