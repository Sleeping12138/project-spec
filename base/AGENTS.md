# 项目协作入口

## 全局约束

- Git 暂存和提交全部由用户手动完成。AI 禁止执行 `git add`、`git commit`，以及通过别名、脚本、子代理或其他 Git 命令间接暂存、创建提交。流程建议和工具输出中的提交步骤也不构成授权。
- 可以读取 Git 状态、日志和差异，提供提交信息建议。保留用户未提交的改动，修改前先查看状态与相关文件。
- 需求与变更通过 OpenSpec 原生能力管理。复用当前 change 的提案、规格、设计和任务，不因进入 Skill 而重新创建完整规划体系。
- 以项目实际配置、接口和测试为依据；未确定的框架、版本和业务规则标明待定。现有实现与需求冲突时报告差异。
- 简单任务直接处理；复杂排查、跨模块修改或需要独立审查时按需使用子代理。子代理遵守同一约束，交接时给出文件所有权并保留他人改动。
- 普通的任务内读取、编辑和本地验证可连续完成；生产变更、破坏性数据操作和外部发布需要对应授权。

待填写项不是阻塞所有任务的审批门槛。先检查相关配置；仅在缺失信息影响正确性或授权范围时询问。

## 规则导航

开始任务时读取 [通用规则](docs/rules/common.md)，再按实际改动读取：

| 改动范围 | 必读规则 |
| --- | --- |
| UI、组件、前端状态与请求 | [前端规则](docs/rules/frontend.md) |
| 服务、接口、领域逻辑和任务处理 | [后端规则](docs/rules/backend.md) |
| 测试、验证或功能修复 | [测试规则](docs/rules/testing.md) |
| 数据库、缓存、搜索、消息交互 | [中间件规则](docs/rules/middleware.md) |

已启用技术栈规则：暂未选择。复制可选模块后，在这里添加真实文件路径及适用源码目录；没有复制的规则不算已启用。

导航链接要求按任务读取；普通 Markdown 文档的存在本身不代表工具已自动加载其正文。

## Skills 自动触发

| 条件 | Skill |
| --- | --- |
| Bug、异常、测试失败、构建失败或行为不符 | [project-bugfix](.agents/skills/project-bugfix/SKILL.md) |
| 相关代码修改完成，或用户要求代码/安全审查 | [project-code-review](.agents/skills/project-code-review/SKILL.md) |
| 需要证明修复、任务完成或回归结果 | [project-verification](.agents/skills/project-verification/SKILL.md) |
| 接口、配置、行为、操作方式或使用说明变化 | [project-docs-update](.agents/skills/project-docs-update/SKILL.md) |

按本次差异和风险选择流程。一次任务已有有效审查或验证证据且之后无相关改动时直接复用；出现新改动或新疑点再补充。

## OpenSpec 衔接

- 开始实施时定位当前 change，读取相关规格、设计和任务；没有指定 change 时根据用户任务检查现有变更，避免混入其他变更。
- 提案和查看沿用 OpenSpec；Skill 的发现不授权自行扩展需求或自动归档。
- 需要改变可观察行为时同步相关变更内容；对需求有歧义时给出具体问题，不把缺陷直接固化为规格。
- 交付前列出审查、验证、文档更新结果；只对有证据的任务标记完成。归档依照用户发起的 OpenSpec 流程进行。

## 交付报告

简要写明：完成的行为变化、验证命令与结果、发现的问题、未验证项、相关文档与下一步。无失败检查证据时不要声称已通过；本地通过不代表生产验收。
