# 通用规则

## 适用范围

适用于所有改动。全局授权和 Git 约束见根 `AGENTS.md`。

## 约束

- 修改前理解相关调用者、接口和已有约定，控制改动范围，保留用户工作。
- 复用项目现有依赖和模式；新增依赖需说明实际用途，遵循项目已有依赖管理要求。
- 数据在边界处校验；来自用户、外部服务、文件和消息的内容均视为不可信输入。
- 密钥通过现有环境配置或密钥管理系统提供；禁止写入源码、测试快照、日志或交付报告。
- 错误显式传播或有记录地处理，保留可诊断上下文；向外返回的错误不暴露内部细节和敏感信息。
- 避免跨模块共享对象的隐式修改。状态所有者内部可采用符合语言和项目惯例的更新方式，跨边界保持明确所有权。
- 命名和组织服从项目已有惯例，保持职责集中；实际重复出现后再提取抽象。
- 不为当前任务附带无关重构、格式化或框架迁移。接口兼容性变化需在需求或变更中说明。
- 日志和观测输出最小化敏感数据；配置缺失在使用边界明确报错，必要配置按项目启动策略校验。

## 检查方法

- 查看本次差异及受影响调用者，确认边界校验、错误处理和兼容性。
- 运行项目适用的格式、静态检查及必要测试；检查日志、配置和新增依赖是否符合项目约定。
- 对新增风险、未执行检查和残留不确定性给出具体说明。
