# 测试与验证规则

## 风险分级

| 风险与示例 | 必要验证 |
| --- | --- |
| 低：文案、局部样式、无行为变化的文档 | 差异检查及相关渲染/链接/静态验证；按实际影响选择 |
| 中：局部逻辑、组件行为、普通 Bug | 对应回归测试和受影响调用者检查；新增或变更逻辑优先测试驱动 |
| 高：权限、资金、并发、跨服务契约、数据库迁移、消息一致性 | 覆盖关键边界的单元、集成/契约及必要端到端验证；包含失败、重试/并发、兼容与恢复场景 |

风险以行为和影响判断，不按代码行数或扩展名判断。混合变更分别判断，关键风险不能被局部小改动掩盖。

## 约束

- 复用项目已有框架、夹具、命令和目录；统一覆盖率阈值由具体项目决定。
- Bug 先取得可复现证据，再补有价值的回归保护；可自动化且影响重要时优先先失败再修复。
- 测试验证需求和边界行为，避免只镜像实现细节、只统计数量或只检查文件存在。
- 不通过删断言、弱化检查或跳过用例制造绿色结果；确认测试本身错误时说明证据并修正。
- 单元、集成、契约和 E2E 按实际风险使用；低风险改动不强制新增全套测试。
- 使用隔离数据和明确环境；外部服务、生产数据和高成本测试按授权范围处理。
- 报告执行命令、结果和适用环境；未运行、依赖缺失、失败分别说明。
- 本地检查、审查、OpenSpec 格式校验都不单独证明目标环境业务验收。

## 检查方法

用需求场景和当前差异检查测试覆盖；先运行最相关检查，因风险、失败或新修改再扩大范围。已有有效证据可复用，相关代码再次修改后重新验证。
