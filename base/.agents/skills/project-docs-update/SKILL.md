# 相关文档更新

## 输入与边界

读取根 `AGENTS.md`、当前差异、相关接口/配置/使用入口和已有文档。OpenSpec 继续拥有行为规格和变更记录；文档更新复用其结论，不复制一份完整需求。

## 流程

1. 从改动确定谁需要知道：使用者、调用方、部署维护者或后续开发者。查找对应 README、接口说明、配置样例、操作指引与已有规则。
2. 对照实现、测试与相关规格找出过期内容。不能由证据确定的行为标明待确认，不替业务所有者作决定。
3. 在现有权威位置更新受影响内容，例如默认值、环境变量、错误响应、调用方式、兼容和迁移步骤。保留真实出处和相关链接。
4. 同一事实在其他位置通过引用连接；不复制完整规格、测试函数清单或临时调试过程。确有新知识所有者缺口时提出最小文档位置，不为目录结构创建空文档。
5. 检查引用路径、命令和示例与实际版本相符。安全且属于任务授权范围的示例可验证；涉及真实服务或破坏性操作时不为验证说明而直接执行。
6. 发现行为规格遗漏时更新当前 OpenSpec 变更或指出待处理差异，避免绕过变更流程直接把未确认行为写入主规格。

## 输出

- 更新的文档、对应行为变化和验证方法。
- 未受影响时简述判断依据；待确认或未验证内容单列。
- 维护性决策有现成记录位置时引用它，不自动引入新治理体系。

Git 暂存提交由用户完成；文档同步不自动发布、归档或修改外部知识库。
